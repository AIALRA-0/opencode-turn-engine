## 这份清单解决什么问题

- 旧 A/B 主要验证服务健康、权限收口和小型代码修复，不能代表高难度 agent 能力
- 新清单从真实公开 benchmark 拉 issue，优先选择难、复杂、但 token 消耗不过分爆炸的任务
- 这一步只是选题和追溯，不等于已经执行官方 SWE-bench harness，下一步需要 clone 仓库、checkout base commit、运行官方测试

## 评分规则

- 难度越高分越高
- fail-to-pass 测试越多分越高
- patch 和 test patch 越复杂分越高，但不会无限加分
- prompt token 越接近目标 token 分越高，太短拉不开差异，太长会浪费模型预算
- 同一仓库限制最多入选数量，避免全被一个项目占满

## 下一步执行方式

1. 用 manifest 里的 repo、baseCommit、instanceID 准备独立工作区
2. agent 只拿 problem statement，不拿 gold patch
3. agent 完成后再应用 test_patch 或调用官方 harness 验证
4. 三方对象继续是 Codex CLI、debug1 原版 OpenCode、AIALRA OpenCode fork
5. A/B runner 用并发执行，但每个任务和对象必须独立目录、独立日志、独立越界路径
